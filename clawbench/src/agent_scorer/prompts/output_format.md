### 输出格式

你的输出必须是 JSON 格式，包含以下字段：

- **rubric_results**：一个对象，键为叶子节点的 id（已在 Rubric 树中方括号中标注，形如 `[node-xxxxxxxxxxxx]`），值为一个对象：
  - `passed`：布尔值，true = 通过，false = 未通过
  - `reasoning`：字符串，说明你做出该判断的具体依据（1-2 句话，引用证据）
  - 必须覆盖所有叶子节点

- **confidence**：你对本次评估整体结果的置信度，取值 0.0-1.0
  - 1.0 = 非常确信，证据充分且无歧义
  - 0.7 = 较为确信，主要判断有依据但部分细节不确定
  - 0.4 = 一般，证据有限或存在矛盾
  - 0.0 = 完全不确定，无法做出可靠判断

- **time_analysis**：字符串，必填。时间窗口分析的**评分过程中的逐项记录**：评到涉时叶子时即时记录其时间分析，不得事后倒填。须包含：
  - 执行日期（UTC+8，权威基准，取自 user prompt 元信息段）
  - 每个涉时叶子节点 id 及其所需的绝对时间窗口
  - Agent 实际使用/产出的日期
  - 逐项满足/不满足结论
  - 若任务无任何时间要求，写"无时间窗口要求"即可满足本字段

- **info_fidelity_analysis**：字符串，必填。搜索信息提取分析的**评分过程中的逐项记录**：评到涉搜叶子时即时记录，不得事后倒填。须包含：
  - 每个涉搜叶子节点 id 及其所需信息（须从搜索/浏览结果获取的部分）
  - 对应的搜索/浏览工具调用及返回内容摘要
  - Agent 交付物中的对应内容
  - 逐项忠实/不忠实结论（编造/误用/替换/断章取义）
  - 若任务不涉及任何搜索/浏览获取外部信息，写"无搜索信息忠实性要求"即可满足本字段

- **needs_human_review**：布尔值，必填，参考评估工作流的**异常与存疑判定**部分填写。

- **review_notes**：字符串，必填（非空）。存疑原因说明：`needs_human_review=true` 时具体写明命中的情形与依据；`needs_human_review=false` 时写"无需人工复核"。

注：字段结构以结构化输出的 JSON Schema 为准；如以上文字描述与 Schema 不一致，以 Schema 为准。
