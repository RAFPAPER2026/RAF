### 评估工作流

1. **阅读任务配置**：查看任务目录，理解任务要求和输入件（如果有）
2. **阅读执行轨迹**：读取结果目录下的 `sessions.json`（user prompt 的「执行轨迹元信息」段已给出执行日期与工具调用序列），了解 Agent 做了什么
3. **检查工作区**：查看结果目录下 `workspace/` 中的文件，验证输出结果；对不同类型的交付物，参照下文"交付物检查规程"选择合适的检查方式
4. **逐叶评分**：对每个 Rubric 叶子节点，基于证据判断通过/未通过，并给出具体理由。
   - 若叶子涉及时效/时间窗口要求（如最新/前N天/未来N天/最近一周等），先按「关键规则 → 时间窗口判据」锚定执行日、换算所需窗口、核对 Agent 实际日期再判 `passed`，并将该分析写入 `time_analysis` 字段；时间窗口不满足即判未通过，不得事后弱化。任务无任何时间要求时，`time_analysis` 写"无时间窗口要求"。
   - 若叶子所需信息来源于搜索/浏览结果，先按「关键规则 → 搜索信息忠实判据」定位搜索返回内容、比对 Agent 交付物是否忠实提取（无编造/误用/幻觉/替换），再将该分析写入 `info_fidelity_analysis` 字段；发现提取不忠实即判未通过，不得事后弱化。任务不涉及任何搜索/浏览获取外部信息时，`info_fidelity_analysis` 写"无搜索信息忠实性要求"。
5. **给出置信度**：评估你对本次评分整体结果的把握程度
6. **存疑判定与异常说明**：判断本次评分是否需要人工复核（存疑），给出结构化的 `needs_human_review` 与 `review_notes`。出现以下任一情形即置 `needs_human_review=true`，并在 `review_notes` 中具体写明命中的情形与依据：
   - **评分过程异常**：评价过程中出现异常，或缺 `sessions.json`/`workspace` 等，导致未能完全按规程评分；
   - **被测模型执行环境有问题**：容器/服务异常、关键工具不可用、环境与任务要求不符，影响了你对交付结果的判断；
   - **query 与实际情况冲突/信息不足/矛盾**：任务要求与 Agent 实际所处情境对不上，导致难以定论；
   - **评测把握不大**：证据模糊、边界情形、置信度低等，对部分判断拿不准时。
   - 若以上均不成立，置 `needs_human_review=false`，`review_notes` 写"无异常情况"。
  注意：无论是否存疑，凡评分过程中出现异常情况（如工具调用失败等），都需要在结果目录的 `verifier/judge/` 文件夹下创建 `exceptions.md` 留作补充说明。
7. **整理证据**：如果产生了关键的评估证据（例如网页截图等），在结果目录的 `verifier/judge/` 文件夹下新增 `proof` 文件夹，并将评估证据存放进去
8. **清理临时文件**：清理在评估过程中生成的临时脚本、文件（非证据）等，但不要删除任何原始文件和环境依赖（例如 playwright 需要的 Chromium 可执行文件等）！
