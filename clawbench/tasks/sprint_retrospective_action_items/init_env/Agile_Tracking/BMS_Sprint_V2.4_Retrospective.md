## 二、What Went Well 👍

### 2.1 SOC估算算法优化

SOC（State of Charge）扩展卡尔曼滤波算法优化工作由赵明辉牵头，提前一天完成交付。新算法在-20°C至60°C温度范围内估算误差降低至±1.5%，较上一版本提升了35%。测试数据已提交至GitLab仓库。

- [x] 完成SOC算法的单元测试用例编写（共147条） @赵明辉
- [x] 在HIL台架上完成72小时耐久性验证 @赵明辉
- [ ] 将SOC算法性能测试报告整理为正式技术文档，提交至Confluence知识库 @赵明辉
- [ ] 基于本次优化经验，编写SOC算法调参指南供新成员参考 @孙丽娜

### 2.2 CAN通信模块

CAN通信协议栈V2.4版本通过了所有50项集成测试用例，代码审查通过率达100%。DBC文件已与整车控制器团队完成对齐。

- [x] 完成CAN通信模块与VCU的联调测试 @王建国
- [ ] [Urgent] 将CAN DBC文件V2.4版本同步至整车电气架构共享文档库，并通知电控团队确认 @王建国

### 2.3 自动化测试

自动化测试覆盖率从上一冲刺的76.1%提升至82.3%，主要覆盖了均衡控制模块和故障诊断模块的边界条件。Jenkins流水线执行时间优化了18%。

- [x] 新增均衡控制模块自动化测试用例（36条） @张雨桐
- [x] Jenkins CI流水线脚本优化完成 @张雨桐

## 三、What Didn't Go Well 👎

### 3.1 OTA升级模块进度滞后

OTA空中升级模块原计划在本冲刺内完成差分包生成与校验功能，但由于FOTA控制器硬件样件延迟到货（3月22日才到），实际只完成了差分包生成的基础框架。校验功能和断点续传机制尚未启动开发。

- [ ] [Urgent] 完成OTA差分包校验算法的详细设计文档，明确SHA-256与CRC32双校验方案 @刘思远
- [ ] 搭建OTA升级的硬件在环（HIL）仿真测试环境，确保FOTA控制器与BMS主控通信链路畅通 @陈晓峰
- [ ] [Urgent] 与供应商沟通FOTA控制器固件V1.2的已知BUG修复时间表，形成书面邮件记录 @刘思远

### 3.2 硬件接口文档更新不及时

本冲刺中有3次因硬件接口文档版本不一致导致的联调返工，累计浪费约1.5个人天的工作量。主要集中在高压采集模块的ADC配置寄存器地址变更上。

- [ ] 建立硬件接口文档的版本变更通知机制，每次变更后24小时内通过企业微信群同步至研发团队 @孙丽娜
- [x] 修复因ADC寄存器地址错误导致的高压采集偏差问题 @陈晓峰

### 3.3 与测试团队沟通瓶颈

本冲刺中有两轮测试因需求描述不清导致测试用例编写偏差，需要重新沟通确认后再执行。建议在下一冲刺引入BDD（行为驱动开发）格式的验收标准。

- [ ] 在下一冲刺的Sprint Planning会议上推行BDD格式的验收标准模板，并准备示例文档 @孙丽娜
- [ ] 针对OTA模块和均衡策略模块，提前编写Gherkin格式的验收场景 @张雨桐
